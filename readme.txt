WordPressの画像をWebP・AVIFなどの次世代画像フォーマットに変換し、サイトの画像を軽量化するプラグインです。

== Description ==

Kashiwazaki Next-Gen Images は、メディアライブラリの画像（JPEG・PNG・GIF・WebP）を WebP・AVIF に変換し、対応ブラウザにだけ軽い画像を配信します。

= 特長 =

* **元の画像は削除も変更もしません。** 変換後のファイルは「元のファイル名.webp」「元のファイル名.avif」として元画像の隣に置きます。
* 新しくアップロードした画像を自動で変換します（時間制限つき。終わらなかった分は WP-Cron または一括変換で続きを処理）。
* 既存の画像を、管理画面から 1 枚ずつ順番に一括変換できます。進み具合はサーバーに保存されるので、別のページへ移っても進捗が出続け、見ている間は処理が進みます。止めても、続きから再開できます。大量の画像は WP-CLI からも変換できます。
* 表示は `<picture>` タグ方式です。AVIF → WebP → 元の画像の順に、ブラウザが使える最初のものを選びます。サーバー側の書き換えルール（.htaccess など）は不要で、ページキャッシュとも衝突しません。
* 変換できない環境・画像でもサイトの表示は壊れません（その画像は元のまま表示されます）。
* ライトボックスなど、画像を包み直す他のプラグインとも共存します（自動で対応）。
* GD と Imagick の両方に対応。初期設定では外部コマンド（exec 等）を使わないので、レンタルサーバー（エックスサーバーなど）でそのまま動きます。
* サーバーの PHP が AVIF を作れないときは、変換プログラムの cavif を追加して AVIF を作れます（任意。設定画面か wp-config.php で cavif の場所を指定したときだけ、そのプログラムを実行します）。

= 安全のための仕組み =

* 変換後のほうが大きいファイルは保存しません。
* アニメーション GIF・APNG・アニメーション WebP は変換しません（動かなくなるため）。
* 「PNG・GIF は劣化なしで変換」を選んでいるときは、PNG・GIF の AVIF を作りません（このプラグインは AVIF を劣化なしで作れず、AVIF 対応のブラウザには WebP より先に配信されるため。切り替えたあとは「一括変換を開始」を押すと、すでにある画像にも反映されます）。この場合は WebP だけを配信します。
* 変換ファイルの名前がシンボリックリンクのときは、配信しません（リンクの先が別の画像のことがあるため）。
* 画像の中身を確かめてから変換します（拡張子を偽ったファイルは処理しません）。
* 元画像が同じ名前で差し替えられた場合、古い変換ファイルは配信しません（ファイルのサイズと更新時刻で差し替えを見つけます。サイズと更新時刻の両方が同じまま中身だけ変えた場合は見つけられないので、画面の「すべて作り直す」か WP-CLI の --force で作り直してください）。
* 変換ファイルが 0 バイトだったり存在しなかったりする画像には何もしません。
* 配信テストで、サーバーが .webp / .avif を正しい種類（Content-Type）で配信できないと分かった形式は、自動的に配信を止めます。
* 他のプラグインが作った変換ファイルは、上書きも一括削除もしません。元画像より新しければそのまま配信に使います。元画像を削除しても、他のプラグインが作った変換ファイルは消さずに残します（消せるのは、このプラグインが作った変換ファイルだけです）。別の画像の本体として登録されているファイルは、どの場合も触りません。
* 管理画面の操作はすべて権限確認と nonce 確認つきです。
* 設定画面は、区画ごとのカード、スイッチ、スライダー、ツールチップで整理されています（スマホ幅にも対応）。

= 対象外 =

* CSS の background-image で指定された画像
* 外部 CDN から配信されている画像
* 画像を JavaScript で別の要素に包み直すプラグイン（ライトボックスなど）がある場合は、包み直されたあとに <picture> を <img> のすぐ外側へ戻す小さなスクリプトを出力して、WebP / AVIF が使われるようにします（設定の「他のプラグインが画像を包み直しても対応」で切り替えられます）。

== Installation ==

1. このフォルダを `/wp-content/plugins/` に置き、プラグイン一覧から有効化します。
2. 管理メニュー「Kashiwazaki Next-Gen Images」を開き、設定を確認します（初期設定のままで動作します）。
3. 既存の画像は「一括変換」タブから変換します。

== Frequently Asked Questions ==

= AVIF が「利用できません」と出ます =
お使いのサーバーの PHP が AVIF の書き出しに対応していません（PHP 8.1 以上で libavif 対応の GD、または AVIF 対応の Imagick が必要です）。WebP だけで動作します。サーバーが対応すると、自動的に利用できるようになります。

= サーバーの PHP が AVIF に対応していなくても、AVIF を作れますか =
変換プログラムの cavif（https://github.com/kornelski/cavif-rs/releases）をサーバーの公開フォルダの外に置き、「設定」タブの「詳細設定」にある「cavif の場所」に、その場所（例: /home/アカウント名/bin/cavif）を入力して保存すると作れます。

ファイルと、それを置いたフォルダの権限は 755 か 700 にしてください。欄の下に「使えます」と表示され、「診断」タブで「cavif（外部プログラム）」の AVIF が「○ 利用可」になれば使えます。PHP から外部のプログラムを実行できないサーバーでは使えません。

場所を入力できるのは、プラグインをインストールできる管理者だけです。入力できるのは、名前が「cavif」で始まるファイルだけです。場所を設定画面から変えられないように固定したいときは、wp-config.php に次の 1 行を足す方法もあります（こちらが優先されます）。

`define( 'KASHIWAZAKI_NEXT_GEN_IMAGES_CAVIF', '/home/アカウント名/bin/cavif' );`

= 配信テストで問題が出ました =
サーバーが .webp / .avif を正しい種類で配信していません。「診断」タブの配信テストに出る「自動で直す」を押すと、プラグインが画像フォルダの .htaccess に種類の指定を書き足して直します（先にテスト用のフォルダで試し、うまくいかないときは何も変更しません）。

自動で直せないとき・手で直すときは、Apache 系のサーバーでは、.htaccess に次の 4 行を追記してから、「診断」タブでもう一度テストしてください。

`<IfModule mod_mime.c>
AddType image/webp .webp
AddType image/avif .avif
</IfModule>`

= 変換ファイルを全部消したい =
「一括変換」タブの「すべての変換済みファイルを削除」の「削除する」を使います。このプラグインが作ったファイルだけが削除され、元の画像は削除されません。

= プラグインを削除したら変換ファイルはどうなりますか =
初期設定では残ります（元の画像と設定の記録だけが対象で、サイトの表示には影響しません）。設定の「プラグイン削除時に変換ファイルも削除」をオンにすると、削除時に消えます。

= WP-CLI で変換できますか =
`wp kashiwazaki-next-gen-images convert`（全件）、`wp kashiwazaki-next-gen-images convert 12 34 --force`（指定した画像を作り直す）、`wp kashiwazaki-next-gen-images status`（状況）が使えます。

== Changelog ==

= 1.0.2 =
* cavif で AVIF を作るとき、1 回の処理の締め切りを見ずに、1 枚の上限（既定 60 秒）まで待っていた問題を直しました。締め切りが近いときは締め切りまでで止めるか、次の回へ回します。締め切りで止めた分は失敗に数えず、次の回で続けて変換します。
* 変換の途中で PHP の処理が終わったとき、動いている cavif を止めてから一時ファイルを消すようにしました。

= 1.0.1 =
* サーバーの PHP（GD・Imagick）が AVIF を作れないときに、変換プログラムの cavif を使って AVIF を作れるようにしました（任意。設定画面の「cavif の場所」に場所を入力したときだけ動きます。wp-config.php でも指定できます）。
* 診断タブと設定の「変換エンジン」に cavif を追加しました。
* サーバーが WebP・AVIF を正しい種類で配信していないときに、診断タブの「自動で直す」で直せるようにしました（画像フォルダの .htaccess に種類の指定を書き足します）。
* 配信テストを、実際の変換ファイルと同じ形の名前で確かめるようにしました。
* 一括変換で、時間の区切りにかかった画像の一部のサイズを取り残して「完了」と報告することがあった問題を直しました（「PNG・GIF は劣化なしで変換」を切り替えたあとなど）。
* 一部の形式・サイズだけ変換できなかった画像も、失敗として数えるようにしました。
* アップロード時の自動変換が、進んでいるのに途中で止まることがあった問題を直しました。
* 「書き足した指定を消す」で、消せなかったときも「消しました」と表示していた問題を直しました。
* 再集計で、消えた変換ファイルを数えないようにしました。一括変換タブの数を「処理が必要」にしました。
* 「PNG・GIF は劣化なしで変換」を切り替えたあとに一括変換が要ることを、画面とマニュアルに書きました。
* 「PNG・GIF は劣化なしで変換」を切り替えても、以前の設定で作った WebP がそのまま使われていた問題を直しました（一括変換で作り直します）。
* 書き込みに失敗した変換ファイルの再試行が毎回失敗すると、自動変換の予約が止まらないことがあった問題を直しました。
